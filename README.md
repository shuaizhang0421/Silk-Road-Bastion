# 丝路堡垒

真 3D 单机丝路守城游戏。当前公开测试版本为 `v0.8.0-playtest`，开放“无尽远征”与“极限守城”；“行者历练”会在首页展示为后续模式，但尚未开放游玩。

## 已实现

- Three.js 真 3D 场景、光照、阴影和雾效
- 连续砖石城墙、唯一城门、院内铺砖与区域专属外部地貌
- 带材质与待机、奔跑动画的完整 3D 丝路行者
- 鼠标点击地面、移动端全屏拖动与双指缩放的统一操作
- 主帐和商栈每 3 秒产币，工坊按木材、石料、机巧轮换生产
- 无尽远征会将真实城防、院落和后勤位置从 6 个逐步扩至 8、10、12 个；极限守城固定 8 个位置
- 建造栏直接显示“产钱、产材料、远程、减速”等用途
- 城门和主帐血条在安全、满耐久时自动收起，受击、低耐久或靠近交互时出现
- 白天与夜袭均可建造；城门升级提高耐久上限但不免费回满，维修需要材料
- 每夜剩余敌人数、明确过关反馈和下一夜推进
- 七类敌人、真正保持射程的游弓手、每 5 夜轮换首领和后期组合机制
- 后期解锁防空连弩与震石投车：前者优先克制飞行机关，后者攻击成群地面敌军
- 60 项以上带流派标签、稀有保底与阵容适配的可叠加遗物
- 无尽远征在 8、10、12 石台后改为选择高台、侧门、商队院或机关阵地；极限守城以战备压力与补给取舍持续推进
- 1x/2x 夜袭速度、20 秒备战和城内立即入夜
- 随机世界、无尽远征、极限守城、三档本地存档与导入导出
- 动态实时 3D 首页封面；行者历练作为后续内容预览保留
- 完全离线实时合成的原创背景音乐：白天舒缓拨弦、夜袭低鼓节奏、选择阶段氛围旋律
- 风声环境音、生产提示、建造、弩箭、撞门、警报和胜利音效
- 手机竖屏、横屏和平板 HUD，全屏点击移动、拖动走位、双指缩放
- GitHub Pages 相对路径构建
- 自动检查无尽与极限各 5000 夜、存档字段范围、资产授权和多端 HUD 资源图标契约
- 首页提供 GitHub 试玩反馈入口，不接入账号、广告或行为追踪

## 本地运行

```bash
pnpm install
pnpm dev
```

浏览器访问终端显示的本地地址。由于 3D 模型通过模块加载，请不要直接双击 `index.html`。

## 构建

```bash
pnpm build
```

静态文件输出至 `dist/`，可直接发布到 GitHub Pages。

完整本地验收可依次运行 `pnpm test:assets`、`pnpm test:save`、`pnpm test:ui`、`pnpm test:regions`、`pnpm test:onboarding`、`pnpm test:sim` 和 `pnpm build`。

## 控制

- 鼠标点击地面：移动到目标
- 鼠标点击资源、事件或设施：自动靠近并互动
- 鼠标点击建筑：显示升级和修缮操作
- 点击底部建筑图标后点击高亮的合法位置：建造
- 右键：取消建造或选择
- 鼠标滚轮：缩放镜头
- 中键拖动：微调镜头
- 移动端：点击地面自动移动，按住拖动持续走位，双指缩放，右侧按钮交互

## 关卡规则

- 驿站主帐提供基础钱币，商栈和工坊每 3 秒结算一次资源。
- 外出采集是额外加速手段，不是每日必做；留在基地也能持续发展。
- 城门被破后，掠夺者会攻击商栈，爆破手会攻击工坊和炮塔，普通敌人攻击附近设施，最后才冲向主帐。
- 准备倒计时结束后进入夜袭。清空全部敌人且驿站核心仍存活，本关胜利。
- 每关结束从三项随机遗物中选择一项，普通、稀有和传奇遗物具有不同叠加上限。
- 每守过三夜才会迁营。第 3、6、9 夜扩展到 8、10、12 个功能位置，之后选择区域防线模块，不再无限放大地图。
- 极限守城永远停留在固定驿站，依靠有限布局、专精与维修决策生存。
- 极限守城每 3 夜获得一次物资补给三选一，但不扩城；无尽远征则迁往随机区域并逐步扩建。
- 行者历练目前仅展示在首页，第一版不开放进入；避免让尚未完成的独立玩法影响守城首版体验。
- 建筑修理不是免费行为：商栈消耗钱币和木材、工坊消耗钱币和石料、武器设施消耗钱币与机巧；完整建筑不会扣费。

## 保存与 GitHub Pages

- 游戏每 5 秒以及建造、结算、迁营时自动保存。首页可切换三个本地档位。
- “导出存档”会下载 JSON 文件，“导入存档”可在另一台电脑、手机或平板恢复进度。
- `pnpm build` 产生的 `dist/` 可直接部署到 GitHub Pages。静态部署无需服务器或账号；跨设备自动同步需要未来接入云端服务。
- 项目已内置 GitHub Actions 工作流。首次发布时，将文件推送至 `main` 分支，然后在仓库的 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**；之后每次推送 `main` 都会自动构建并更新页面。
